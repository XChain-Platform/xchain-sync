WHY THE ZERO IS BELIEVABLE. A sweep that reports nothing to delete can be
a clean tree or a broken tool, and the two read identically. So the tool
was falsified rather than trusted: two modules were planted under src/ and
staged, one required by nothing and one required only by a new test file.
The sweep named both, the first as unreferenced across the platform and
the second as held by tests alone, which is the shape the structure
standard reads as dead rather than as a reason to keep a file. Both plants
were then removed and the sweep returned to zero.

THE PORTED TOOL WAS ADAPTED BEFORE IT WAS BELIEVED. Its first run reported
sibling references that belonged to another service: the reference regexes
spelled that service name as a literal, so the cross-repo half answered a
question about the wrong repo while the totals still looked plausible.
Every regex is now built from one name constant, and the counts below are
the corrected ones.

COMPUTED REQUIRES. A static walk cannot follow a require built at run time,
so a file held only by one reads dead. All four computed forms were swept
across src, test and bin: this repo builds no require of its own source at
run time. Two test files require a JSON fixture through path.join and
neither names a src path. One dynamic edge is declared ahead of the db
split, inert until src/db/index.js exists.
